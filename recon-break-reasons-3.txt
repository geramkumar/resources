What CTC Can Handle Automatically
CTC is very strong at rule-based and algorithmic matching.

| Break Type              | Can CTC Handle Automatically? | How                          |
| ----------------------- | ----------------------------- | ---------------------------- |
| Reference mismatch      | Often yes                     | Composite attribute matching |
| Amount difference       | Yes                           | Tolerance rules              |
| Timing difference       | Yes                           | Date tolerance window        |
| Net vs gross settlement | Yes                           | Many-to-one matching         |
| Partial settlement      | Yes                           | One-to-many matching         |
| Duplicate transactions  | Yes                           | Duplicate detection rules    |

What CTC Usually Cannot Resolve Automatically
Some breaks require information outside the reconciliation data.

| Break Type                  | Why CTC Cannot Fully Resolve                 |
| --------------------------- | -------------------------------------------- |
| Missing transaction         | Needs investigation whether payment was sent |
| Counterparty issue          | Requires confirmation from another bank      |
| Interface / ETL failure     | Data never reached reconciliation system     |
| Data mapping errors         | Upstream integration problem                 |
| Invalid beneficiary details | Payment rejected by receiving bank           |





Below are the common reconciliation break scenarios, along with possible reasons and potential solutions.
These examples reflect how Ops teams typically handle breaks in systems like Clareti Transaction Control, often involving confirmations exchanged through SWIFT.

1. Missing Transaction

Example

| System   | Ref     | Amount |
| -------- | ------- | ------ |
| Internal | TXN1001 | $5,000 |
| External | —       | —      |


Possible Reasons

SWIFT message not sent

File ingestion failure

Upstream system outage

Payment stuck in gateway

Potential Solutions

Check message queue / gateway logs

Re-send payment message

Reprocess missing file

Implement monitoring alerts for missing feeds

2. Reference Mismatch

Example

| Internal Ref | External Ref | Amount |
| ------------ | ------------ | ------ |
| TXN1002      | ABC77821     | $3,000 |


Possible Reasons

Different systems generate different references

Field truncation during message transmission

Wrong field mapping during ETL

Intermediary bank replaced reference

Potential Solutions

Use composite matching keys (amount + date + currency)

Map internal reference to SWIFT reference field

Normalize reference formats (remove special characters)

Improve interface mappings

3. Amount Difference

Example

| System    | Amount  |
| --------- | ------- |
| Internal  | $10,000 |
| Statement | $9,990  |


Possible Reasons

Correspondent bank fee

FX conversion difference

Rounding differences

Partial settlement

Potential Solutions

Configure tolerance matching rules

Record fee entries separately

Capture FX rate information in reconciliation data

Enhance reconciliation rule logic

4. Timing Difference

Example

| System    | Date   |
| --------- | ------ |
| Internal  | 16 Mar |
| Statement | 17 Mar |


Possible Reasons

Settlement processed next day

Batch processing delays

Time zone differences

Clearing cycle timing

Potential Solutions

Allow date tolerance window (±1 day)

Align batch schedules across systems

Run reconciliation after settlement window closes

5. Duplicate Transaction

Example

| Ref     | Amount |
| ------- | ------ |
| TXN1004 | $2,000 |
| TXN1004 | $2,000 |


Possible Reasons

Retry mechanism resending message

System replay during failure recovery

Duplicate file processing

Potential Solutions

Implement duplicate detection rules

Use unique transaction identifiers

Add idempotency checks in processing systems

6. Net vs Gross Settlement

Example

Internal

| Ref     | Amount |
| ------- | ------ |
| TXN2001 | $100   |
| TXN2002 | $200   |
| TXN2003 | $300   |


Statement

| Settlement | Amount |
| ---------- | ------ |
| SETTLE01   | $600   |


Possible Reasons

Clearing system performs net settlement

Payment network aggregates transactions

Potential Solutions

Configure many-to-one reconciliation rules

Capture settlement batch IDs

Use grouping rules in reconciliation engine

7. Partial Settlement

Example

Internal

| Ref     | Amount |
| ------- | ------ |
| TXN3001 | $8,000 |


Statement

Ref	Amount
| Ref      | Amount |
| -------- | ------ |
| TXN3001A | $5,000 |
| TXN3001B | $3,000 |


Possible Reasons

Liquidity limits

Payment split across settlement cycles

Clearing house partial processing

Potential Solutions

Enable one-to-many matching rules

Capture parent transaction ID

Improve settlement reporting

8. System / Interface Failure

Example

| Internal | External |
| -------- | -------- |
| TXN4001  | Missing  |


Possible Reasons

File transfer failure

ETL job failure

API integration issue

Data parsing error

Potential Solutions

Add automated job monitoring

Implement retry mechanisms

Maintain reconciliation feed audit logs

Alert Ops team for ingestion failures

9. Counterparty Investigation

Example

| Internal | Status |
| -------- | ------ |
| TXN5001  | Sent   |


External bank reports no credit.

Possible Reasons

Incorrect beneficiary account

Compliance hold

Payment rejected by receiving bank

Sanctions screening issue

Potential Solutions

Contact counterparty bank via SWIFT inquiry

Correct beneficiary details

Reprocess payment

Update payment validation rules

10. Root Cause Analysis (RCA)

After resolving breaks, Ops teams classify the cause.

Possible Reasons Categories

Data mapping issue

Fee deduction

Settlement timing difference

Interface failure

Counterparty rejection

Potential Solutions

Improve reconciliation rules

Fix upstream data mapping

Automate tolerance matching

Implement monitoring dashboards

Enhance upstream validations

Simplified Break Resolution Flow
Transaction ingestion
        │
        ▼
Matching rule executed
        │
        ▼
Break detected
        │
        ▼
Ops investigation
        │
        ├─ Identify root cause
        ├─ Apply manual matching / allocation
        ├─ Contact counterparty if needed
        └─ Record RCA
        │
        ▼
Process improvement / rule update
