Below is the end-to-end runbook I would use for your scenario: a secured Azure Databricks multi-tenant workspace, no public network access, no cluster policies, Tenant A has Python dependencies in /Volumes/tenant_shared/tenant_a/python_packages/, GitLab is the CI/CD system, and the design must have a clean path to Serverless.

One important correction from the earlier design: for classic compute, the init script is the fallback mechanism because you explicitly don't want cluster policies; for Serverless, the init script is not used at all. Serverless uses task/job environments and dependencies. Databricks explicitly states that serverless does not support init scripts or compute policies.

Also, for your specific requirement of "copy libraries from DEV to PREPROD", I recommend promoting the exact dependency artifact, rather than copying whatever happens to be installed on a DEV cluster. The source of truth is Git + the approved package artifact.

Part 1 — Decide exactly what is promoted

Before creating anything, establish this rule:

Item	Source of truth	Promoted?
Notebook code	Git	Yes
DAB job definitions	Git	Yes
requirements.txt	Git	Yes
Python wheels	Artifact/UC Volume	Yes
Environment variable names	Git	Yes
Environment variable values	Environment config	Yes
Secret values	Key Vault	No
Secret names	Git/config	Yes
DEV cluster	Databricks	No
PREPROD cluster	Databricks	No
Installed pip state	Cluster	No

The key principle is:

Promote the desired state, not the state of a running DEV cluster.

Part 12 — Prepare the init script

Create:

init_scripts/install_tenant_a_libraries.sh

Use:

#!/bin/bash

set -Eeuo pipefail

REQUIREMENTS_FILE="/Volumes/tenant_shared/tenant_a/python_packages/tenant_a_requirements.txt"

LOG_DIR="/tmp/tenant-a"
LOG_FILE="${LOG_DIR}/library-install.log"

mkdir -p "${LOG_DIR}"

exec > >(tee -a "${LOG_FILE}") 2>&1

echo "=============================================="
echo "Tenant A Python dependency installation"
echo "UTC start: $(date -u '+%Y-%m-%dT%H:%M:%SZ')"
echo "=============================================="

if [[ ! -f "${REQUIREMENTS_FILE}" ]]; then
    echo "ERROR: requirements file not found:"
    echo "${REQUIREMENTS_FILE}"
    exit 10
fi

echo "Python:"
python --version

echo "pip:"
python -m pip --version

echo
echo "Requirements:"
cat "${REQUIREMENTS_FILE}"

echo
echo "Installing dependencies..."

python -m pip install \
    --disable-pip-version-check \
    --no-cache-dir \
    --requirement "${REQUIREMENTS_FILE}"

echo
echo "Checking dependency consistency..."

python -m pip check

echo
echo "Installed packages:"
python -m pip list

echo
echo "=============================================="
echo "Tenant A dependency installation SUCCESS"
echo "UTC end: $(date -u '+%Y-%m-%dT%H:%M:%SZ')"
echo "=============================================="
Why this is production-friendly

It:

fails the cluster startup if installation fails
uses a pinned requirements file
runs pip check
produces an installation log
doesn't contain credentials
doesn't access public PyPI directly if your package source is private

Databricks states that a cluster-scoped init script returning a non-zero exit code causes cluster startup to fail.

Part 24 — Create validation notebook

Create:

notebooks/validate_environment.py
import importlib
import os


REQUIRED_ENVIRONMENT_VARIABLES = [
    "TENANT_ID",
    "APPLICATION_NAME",
    "DEPLOYMENT_ENV",
    "SECRET_SCOPE",
]


REQUIRED_PACKAGES = [
    "pandas",
    "numpy",
    "requests",
    "openpyxl",
    "yaml",
    "jsonschema",
    "cryptography",
    "tenacity",
]


def validate_environment_variables():
    missing = [
        name
        for name in REQUIRED_ENVIRONMENT_VARIABLES
        if not os.getenv(name)
    ]

    if missing:
        raise RuntimeError(
            f"Missing environment variables: {missing}"
        )


def validate_packages():
    failures = []

    for package in REQUIRED_PACKAGES:
        try:
            module = importlib.import_module(package)

            version = getattr(module, "__version__", "unknown")

            print(
                f"{package}: import OK; version={version}"
            )

        except Exception as exc:
            failures.append(
                f"{package}: {exc}"
            )

    if failures:
        raise RuntimeError(
            "Package validation failed:\n"
            + "\n".join(failures)
        )


def validate_secret():
    scope = os.environ["SECRET_SCOPE"]

    value = dbutils.secrets.get(
        scope=scope,
        key="environment-validation"
    )

    if not value:
        raise RuntimeError(
            "Environment validation secret is empty."
        )

    print("Secret retrieval: OK")


def main():
    print("================================")
    print("Tenant A environment validation")
    print("================================")

    print(
        f"Tenant: {os.environ['TENANT_ID']}"
    )

    print(
        f"Environment: {os.environ['DEPLOYMENT_ENV']}"
    )

    validate_environment_variables()
    validate_packages()
    validate_secret()

    print("================================")
    print("VALIDATION PASSED")
    print("================================")


main()

Never print the actual secret.

Part 27 — Future serverless job

Do not try to use the init script for this.

Serverless job tasks have their own environment/dependency model. Databricks supports dependencies from UC Volumes and requirements.txt references for serverless environments.

Your future serverless configuration should conceptually be:

tasks:

  - task_key: main

    notebook_task:
      notebook_path: ../notebooks/main.py

    environment_key: tenant_a_serverless

    environment_variables_key: tenant_a_variables


environments:

  - environment_key: tenant_a_serverless

    spec:
      environment_version: "5"

      dependencies:
        - -r /Volumes/tenant_shared/tenant_a/python_packages/tenant_a_requirements.txt


environment_variables:

  - environment_variables_key: tenant_a_variables

    variables:
      TENANT_ID: TENANT_A
      APPLICATION_NAME: tenant-a-platform
      DEPLOYMENT_ENV: PROD
      SECRET_SCOPE: tenant-a-prod
      LOG_LEVEL: WARN

Serverless environment variables require the appropriate workspace preview to be enabled and are available to the task process; they are not Spark execution variables.

Validate this DAB schema against the Databricks CLI/DAB version certified by your platform team before production deployment, because serverless environment-variable support is still evolving.

    --find-links wheelhouse \
    --requirement requirements/tenant_a_requirements.txt

Then:

python -m pip check

This gives you a self-contained dependency artifact.

Part 40 — Update init script to use release path

Rather than:

/Volumes/.../tenant_a_requirements.txt

use:

/Volumes/tenant_shared/tenant_a/python_packages/current/tenant_a_requirements.txt

The init script becomes:

#!/bin/bash

set -Eeuo pipefail

REQUIREMENTS_FILE="/Volumes/tenant_shared/tenant_a/python_packages/current/tenant_a_requirements.txt"

if [[ ! -f "${REQUIREMENTS_FILE}" ]]; then
    echo "ERROR: Requirements file not found"
    echo "${REQUIREMENTS_FILE}"
    exit 10
fi

python -m pip install \
    --disable-pip-version-check \
    --no-cache-dir \
    --requirement "${REQUIREMENTS_FILE}"

python -m pip check

Now rollback is:

current
  ↓
2026.08.30.1

rather than changing the cluster.

Part 41 — But be careful with rollback

Changing:

current

doesn't change an already-running Python environment.

Therefore:

change current
      ↓
restart cluster
      ↓
init script
      ↓
new dependency version

Databricks documents that changing an init script requires affected clusters to be restarted; the same operational principle applies to dependency changes made through the startup process.

The three rules I would put in the architecture document

Rule 1 — Git is the source of truth.

Never copy a running DEV cluster to PREPROD.

Rule 2 — The dependency artifact is immutable.

Promote the exact tested wheel/requirements artifact from DEV → PREPROD → PROD.

Rule 3 — Keep application configuration independent of compute.

The notebook should know:

os.environ["TENANT_ID"]
os.environ["DEPLOYMENT_ENV"]
os.environ["SECRET_SCOPE"]

but should not know whether it is running on:

All-Purpose

or:

Serverless

That gives you a clean architecture today with no cluster policies, while preserving a realistic migration path to Serverless tomorrow. The only component that is intentionally classic-compute-specific is install_tenant_a_libraries.sh; Serverless replaces that mechanism with its native environment/dependency facility.
